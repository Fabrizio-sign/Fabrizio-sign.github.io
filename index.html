Spotify: creating a playlist

Iker Fabrizio Hernández · Tecnológico de Monterrey · Visual Design + UX/UI · November 3, 2026

1.Selected application

I documented the desktop app of Spotify (Premium plan). The task is to create a new playlist and fill it with songs that fit together.

App
Spotify (desktop, Premium)
Feature
Create a playlist and add songs
Task
Build a playlist with one style

My screenshots are in Spanish; the captions use the English labels.

2.Current user flow

To get the first song into a new playlist I need four actions:

Your library→ 1. Create→ 2. Playlist→ 3. Add→ 4. ⊕ on a song

3.UX analysis

  • How many steps? Four actions to add the first song, then one click per song.
  • Is the navigation clear? Yes. Create → Playlist is simple and “Playlist” is the first option.
  • Is the feature easy to find? Yes. Create is always visible in the Library panel.
  • Are the buttons easy to identify? Mostly. In the Search panel one column mixes a ✓, a ⊕ and a › with no labels (A).
  • Is the information well organized? Not completely. Recent searches and suggestions share one panel without a clear separation (B).
  • Confusing moments: “Let’s find content for your playlist” (C) suggests songs chosen for my playlist, but my playlist is Spanish-language rock and the suggestions included an electronic remix, an urban track and a TV-series soundtrack. Nothing explains why, and I can’t remove them.
Problem I chose to solve: the suggestions don’t match the style of my playlist, and I can’t understand or change them.

What I would change: keep Create → Playlist as it is and improve the suggestions, so they follow the playlist and the user can control them.

4.Design proposal

The panel shows what the suggestions are based on (the style, language and era of the songs already in the playlist) as chips the user can switch off. Each suggestion says what it matches, and a ✕ hides the ones the user doesn’t want.

  1. 1
    ChipsStyle, language and era of the playlist. Tap one to stop matching it.
  2. 2
    Reason lineEach suggestion says what it matches.
  3. 3
    ✕ HideRemoves a suggestion the user doesn’t want, next to the ⊕.

Other changes

  • Steps: the Find songs panel opens by default on a new playlist, so the first song takes 3 actions instead of 4.
  • Colors: a dark base, violet for the main action (⊕) and amber for what the user can change (chips). Spotify’s green is not used.
  • Typography and icons: one typeface (Inter) in regular and bold, and one set of simple line icons.
  • Feedback: a short message after hiding a song, with an Undo button.

5.Proposed user flow

The first two steps don’t change. The rest works like this:

1. Create→ 2. Playlist→ 3. ⊕ first song→ Suggestions match it→ ⊕ add · ✕ hide · chip

7.Justification

  • UX (clarity and ease of use): the problem I found, suggestions that seem random, is solved by showing what they are based on and letting the user change it. The steps that already worked stay the same.
  • UI and visual hierarchy: the chips are boxed at the top because they control everything below. The ⊕ is the strongest button and the ✕ is quieter, so it is available but not distracting.
  • Consistency: all four screens use the same colors, typeface and icons. Violet always means “add” and amber always means “what the suggestions match”.
  • Creativity: instead of only changing how the list looks, I changed what the panel does: it explains its suggestions and accepts the user’s corrections.
  • Less effort: one fewer action to the first song, and one click to hide a song that doesn’t belong.

Note: the mockups use a small set of example songs. A real version would need Spotify’s own data to decide what each song matches.
